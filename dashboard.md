# Dashboard API Contract

This document defines the backend API required by the Nexus FMS Dashboard page.

The Dashboard and Analytics pages are intentionally separate:

- `/dashboard` provides real-time operational information for today.
- `/analytics` provides historical revenue, booking, and performance reporting.

Dashboard data should not duplicate Analytics summary cards such as total revenue, monthly revenue trends, average booking value, or long-term booking charts.

## Recommended endpoint

```http
GET /dashboard
```

### Query parameters

| Parameter | Type | Required | Description |
|---|---|---:|---|
| `date` | `date` | No | Dashboard operating date. Defaults to today in the requested timezone. Format: `YYYY-MM-DD`. |
| `futsal` | `uuid` | No | Filter by a specific facility. |
| `timezone` | `string` | No | Timezone used for date and time calculations. Example: `Asia/Kathmandu`. |

Example:

```http
GET /dashboard?date=2026-09-05&timezone=Asia%2FKathmandu
```

## Required response sections

### Operational stats

The dashboard uses these as today-focused cards:

- `todays_bookings`: Number of bookings for the selected operating date.
- `upcoming_bookings`: Number of future bookings remaining today.
- `available_slots`: Number of slots with `AVAILABLE` status.
- `total_slots`: Total slots configured for the selected date.
- `occupancy_percent`: Occupied slots divided by total slots, multiplied by 100.
- `todays_revenue`: Revenue generated by today's bookings.

The dashboard should not receive `total_revenue`, monthly revenue totals, or historical growth percentages here. Those belong to `/analytics`.

### Slot availability

Return one item for every slot on the selected date, ordered chronologically by `start_time`.

Allowed slot statuses:

- `AVAILABLE`
- `BOOKED`
- `BLOCKED`

Required fields:

- `slot_id`
- `date`
- `start_time`
- `end_time`
- `status`
- `price`

The dashboard renders these as hourly blocks such as:

```text
6:00 AM – 7:00 AM
7:00 AM – 8:00 AM
8:00 AM – 9:00 AM
```

### Today's schedule

Return today's upcoming bookings ordered by `start_time`.

Required fields:

- `booking_id`
- `booking_reference`
- `start_time`
- `end_time`
- `full_name`
- `futsal_name`
- `status`
- `payment_status`

Recommended booking statuses:

- `PENDING`
- `CONFIRMED`
- `CANCELLED`
- `COMPLETED`
- `RESCHEDULED`

The API may omit past bookings or return them with a separate `is_past` field if the backend needs to show the complete daily schedule.

### Facility snapshot

This section provides useful operational context without duplicating Analytics.

- `next_closed_date`: The next date returned by the Closure API.
- `next_available_slot`: The earliest available slot from now onward.
- `peak_booking_window`: The most frequently booked time window based on recent operational data.
- `most_used_slot_duration`: Optional operational insight in minutes.

If a value is unavailable, return `null` instead of an empty string.

## Optional supporting endpoints

The recommended implementation is one aggregated endpoint:

```http
GET /dashboard
```

If the backend prefers smaller resources, these endpoints can be provided:

```http
GET /dashboard/summary
GET /dashboard/slot-availability
GET /dashboard/todays-schedule
GET /dashboard/facility-snapshot
```

All endpoints should accept:

```text
date
futsal
timezone
```

## Error response

Use a consistent error structure:

```json
{
  "success": false,
  "message": "Dashboard data could not be loaded.",
  "errors": {
    "date": ["Date must use YYYY-MM-DD format."]
  }
}
```

Recommended HTTP statuses:

- `200`: Successful response
- `400`: Invalid date, facility, or timezone
- `401`: Unauthenticated
- `403`: User cannot view the facility dashboard
- `404`: Facility not found
- `500`: Unexpected server error

## Backend calculation rules

### Occupancy

```text
occupancy_percent = booked_slots / total_slots * 100
```

Decide whether cancelled bookings count as occupied. The recommended behavior is to exclude cancelled bookings.

### Available slots

Only slots with status `AVAILABLE` should be counted as available.

### Upcoming bookings

Count bookings whose start time is later than the current time in the requested timezone and whose status is not `CANCELLED`.

### Today's revenue

Use the booking amount for bookings created for the selected date. The backend should document whether pending payments are included. The recommended behavior is:

- Include `PAID` bookings.
- Include cash bookings confirmed by the admin.
- Exclude cancelled bookings.
- Exclude unpaid bookings unless the business explicitly counts reservations as revenue.

## Access and performance requirements

- Require an authenticated admin user.
- Apply facility-level permissions before returning data.
- Use the supplied timezone for date boundaries and time comparisons.
- Return slots and bookings in stable chronological order.
- Return `null` for unavailable optional values.
- Cache or efficiently query the selected date because this endpoint powers the first dashboard screen.
- Do not use frontend dummy values after backend integration; map the UI to the `/dashboard` response.

## Frontend integration mapping

| Dashboard UI section | Response path |
|---|---|
| Today’s bookings card | `data.operational_stats.todays_bookings` |
| Upcoming bookings card | `data.operational_stats.upcoming_bookings` |
| Available slots card | `data.operational_stats.available_slots` |
| Occupancy card | `data.operational_stats.occupancy_percent` |
| Today’s revenue card | `data.operational_stats.todays_revenue` |
| Slot availability timeline | `data.slot_availability` |
| Today’s schedule | `data.todays_schedule` |
| Facility snapshot | `data.facility_snapshot` |
| Facility name and hours | `data.facility` |
